# 参考检索与风格学习

## 定义检索范围

从用户论文提取：学科、研究对象、细分问题、方法类别、图类型、重要术语及同义词。先查用户论文引用的代表作与正式论文页面，再进行学术检索。搜索摘要只能用于发现候选；风格判断必须来自真实图例。

记录检索当天日期、查询式、平台、命中来源和排除理由，保存为 `参考文献/检索记录.md`。优先访问出版社、会议论文集、学术机构库、作者公开稿或正式预印本平台。

## 20篇如何选

1. 优先收集同领域同细方向的经典工作。经典的证据可以是奠基性贡献、后续工作持续采用的表达范式、权威综述对其地位的明确说明；记录证据链接和判断理由，不靠“看起来有名”。
2. 用同方向近期优质工作补足新方法和新视觉表达。近1—3个月指执行日前最近三个日历月的滚动窗口，包含最近一个月；记录真实发表/首次公开日期与版本日期，不能用检索时间冒充发表时间。质量依据包括相关性、方法与图注是否清晰、正式评审状态及证据完整度；新预印本注明状态。
3. 同方向不足时，向同领域其他细方向的经典图例扩展，明确可迁移部分和语义差异。

不设机械的三档配额。优先级内还要考虑图类型相关性、表达清晰度和样本多样性。20篇同一团队同一模板的论文可能掩盖其他惯例，应保留选择理由与差异观察。

预印本、会议版、期刊扩展版若属于同一研究工作，原则上合并为一个条目，选择最适合学习且可访问的版本。每篇记为 `P01`—`P20`，图记为 `P01-Fig2`；图数可以多于20，论文计数不可用面板数替代。

## 下载与提图

保存 `参考文献/P01/paper.pdf`，验证文件能打开且标题、作者与记录一致。记录下载 URL、日期和 SHA-256；不能把 HTML 错误页当 PDF。访问失败时尝试作者稿或合法开放版本，仍失败则保留候选记录并寻找符合优先级的替代。

每篇提取至少一张相关图；复杂论文可选2—3张互补图。保留：

- `page-005.png`：完整源页面，帮助核对图注与上下文。
- `P01-Fig2.png`：完整图区域，含所有子图、坐标、图例；图注可以独立保存。
- `P01-Fig2.json`：PDF身份、页码、裁切框与导出参数。
- `caption.md`：图注及理解；逐字内容只保存在本地研究资料中，公开发布遵守来源许可。

**先渲染整页，再识别边界并裁切。** PDF里的一个嵌入图片不一定是一张完整论文图：线条、文字和图例可能是独立矢量对象。自动提取嵌入位图只能辅助定位，不能作为完成证明。

可用 `scripts/pdf_figures.py`：

```bash
python scripts/pdf_figures.py render --pdf "paper.pdf" --pages 3,5-6 --out "pages"
python scripts/pdf_figures.py crop --pdf "paper.pdf" --page 5 --box 0.08,0.12,0.92,0.58 --figure-id P01-Fig2 --out "figures"
```

页码从1开始；裁切框为已渲染页面从左上到右下的归一化坐标。脚本处理整页可见内容，包括矢量图与文字；边界和图注归属由智能体看图确认。扫描稿可用 OCR 辅助检索，OCR结果需对照原图。

## 逐篇学习，才能汇总

`文献清单.csv` 字段由初始化脚本建立。`逐篇学习记录.md` 每篇至少写：

1. 论文身份、优先级和入选依据。
2. 图号、页码、类型、该图实际解释的问题。
3. 观察到的布局、层级、色彩语义、符号、字体、连线和图例组织。
4. 本图可借鉴的一条具体做法，以及不适用或需警惕的部分。
5. 图像路径、已目视核查状态。

制作覆盖全部图例的缩略对照索引，每个缩略图清楚标注论文ID和图号；细节判断回到原图放大核查，不能只看小缩略图。记录“20篇中实际观察到多少篇支持本特征”，分母必须真实。

## 从规律到规则

使用 [风格总结模板](../assets/templates/初步总结风格.md)，把知识分成三层：

- **规则表**：特征、图例依据、适用理由、在本图中的实现。
- **视觉参数**：目标尺寸、面板网格、字体层级、线宽、色板及各颜色含义、箭头/线型语义、间距。数值由目标版面与参考学习决定。
- **不采用的做法**：与本图任务或科学语义不匹配的效果，以及取舍原因。

例如：“P03-Fig1与P11-Fig2将主通路用实线、辅助信息用虚线区分；本图对已执行流程用实线，对可选反馈用虚线，并在图例说明。”这比“简洁、高级、顶刊风”更可执行。

风格学习通过显式文件在本任务中逐轮积累，并不意味着模型权重获得训练。跨任务迁移时先确认领域、图类型和适用条件，不能把一个领域的视觉规则推广到所有学科。

## 访问不足时

记录实际获取和核查数量、未解决条目、已尝试来源与替代路径。继续需求梳理和已有图例学习。需要用户补充访问权限或明确降低参考数量时，仅询问该阻塞点；未获得改变范围的指示前，不以不足20篇的结果冒充标准流程完成。
