# 设计说明

## 从需求到执行

这个 Skill 保留原始流程的20篇学习、六版生图、五轮返工和最终软件重绘，重点补全每一步的输入、产物与完成条件。

| 原始意图 | 落地方式 |
| --- | --- |
| 充分理解论文和提示词 | 保留原始提示词，明确图意、位置和每项内容的科学出处 |
| 向前辈反复学习 | 逐篇观察记录、带图号的风格规则、每轮增量学习 |
| 判断哪里不够好看 | 对照具体位置、参考图、阅读影响、修改动作与通过条件 |
| 固定五轮返工 | `返工n → 版本n+1`，五份返工与六个真实生成版本 |
| 基本1∶1重绘 | 保持布局、层级和语义，纠正乱码、假刻度等生成错误 |
| 最终图由软件产出 | 可编辑图元/代码、实际数据、重绘源文件与重新导出验证 |
| 统一审美要求 | 六项图面表达要求进入提示词、返工与终稿检查 |

## 三个设计原则

**第一性原理：** 一张论文图先回答“帮助读者理解什么”，再决定颜色、图元和版式。每个视觉元素都应承担信息。

**对抗性审查：** 评审者需要指出具体缺陷和可验证的改动。对参考图本身也保留判断，不把相似当作正确，不为凑返工虚构问题。

**奥卡姆剃刀：** 两个入口共用一条主流程。只有两个稳定、重复的文件操作写成辅助脚本，其余判断由智能体完成。重绘工具按图的需要选择。

## 文件分工

`SKILL.md` 是智能体入口，保留共用流程与完成条件。`references/` 放阶段细节，在对应步骤按需读取；`assets/templates/` 提供实际工作记录模板。README面向使用者，介绍安装和调用。

六项图面要求集中定义在 Skill 中，其他文档通过链接和检查项引用，避免维护多个不同版本。

## 已考虑的执行情形

- 同一论文不同出版版本合并计数，确保20篇代表20个研究工作。
- 近期文献窗口按任务执行日计算，覆盖最近三个日历月。
- PDF先渲染再裁切，保留嵌入位图之外的文字和矢量元素。
- 断点续作核对真实文件，不以状态数字或空模板冒充结果。
- 数据缺失时先推进有证据的部分，定量结论始终来自真实数据。
- 只有PDF稿件时交付明确插入位置和图件；实际修改需要可编辑来源。

## 审核中文版本时建议关注

1. 两种场景的范围与默认图数是否符合你的使用习惯。
2. 六项图面表达要求是否足够直接、具体。
3. 文献选择与五轮对照是否真正体现反复学习。
4. 最终软件重绘和交付内容是否符合你的论文工作流。

英文版以验收后的中文规则为准，保持流程、文件约定和验收条件一致。
